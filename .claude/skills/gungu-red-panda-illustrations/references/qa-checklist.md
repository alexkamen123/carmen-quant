# QA Checklist

## 必过项

- 是 16:9 横版。
- 背景是干净白底。
- 有滚滚小熊猫。
- 滚滚承担核心动作，不只是装饰。
- 滚滚保持 IP 识别点：橙红毛发、白色脸部花纹、深棕脸颊、环纹尾巴、耳机或 PM 工具。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。
- 绿色或黄色只作少量辅助，不抢结构。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 滚滚像浣熊、狐狸、机器人、表情包或儿童卡通。
- 滚滚只是抱着咖啡或电脑站在角落。
- 滚滚没有环纹尾巴、白脸花纹或深棕脸颊。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 颜色太花、太像商业海报，或只有蓝紫科技感。

## 迭代方法

- 太普通：让滚滚成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 thoughtful、focused、professional、not childish、not plush toy、not mascot poster。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和滚滚动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。
- IP 漂移：读取 `~/Documents/小浣熊IP资产/README.md` 和四张角色说明书，重新写入小熊猫识别点。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构，并且能认出这是滚滚这个小熊猫产品经理在处理问题。

如果第一眼像教程页、商业插画或普通动物贴纸，就不合格。
