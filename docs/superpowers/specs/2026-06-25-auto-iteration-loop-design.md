# 卡门智投 · 自动迭代 Loop 设计

> 状态：approved 2026-06-25 | 北极星：每轮迭代必须服务「证明价值/帮用户赚钱」，非堆功能

## 目标
让系统围绕「证明价值」自动持续迭代：每轮由数据（价值记分牌）驱动选题，自动写代码、自我挑刺、
通过硬闸门后自动合并上线，再据结果规划下一轮。

## 三模块（单轮闭环）
```
策划(Plan) → 推进(Build) → 审查(Review) → 闸门(Gate) → 合并(Merge) → 再规划 → …
```

### 1. 策划 Plan
- **必须**先跑价值记分牌：`compute_value_metrics` + `accuracy_summary` + behavior/dip，
  取「命中率 / alpha / 用户行为盈亏 / 漏报」里**最差的一项**作为本轮目标。
- 产出**单点 PRD**：只干一件事，强制填「成功标准 = 某赚钱指标从 X → Y」。
- 无明确可改进的赚钱指标 → 跳过本轮（不为做而做）。

### 2. 推进 Build
- 按 PRD 走 TDD（RED-GREEN-REFACTOR），在 worktree 隔离分支写代码 + 测试。
- 遵守范围上限：单轮 ≤ 8 文件 / ≤ 400 行；超了拆轮。

### 3. 审查 Review（对抗式）
- 挑刺四问：能跑吗 / 有回归吗 / 范围超了吗 / **和赚钱有关吗**。
- 北极星相关性**一票否决**：改动不触及任何赚钱指标 → 打回。

## 闸门 Gate（全自动合并的护栏）
自动 merge **必须同时满足**：
1. 全量 `pytest` 0 fail（已知正交 `test_guards`（worktree 缺 gitignore portfolio.yaml）除外）
2. 零回归：合并前测试通过数 ≥ 基线
3. 范围 ≤ 8 文件 / ≤ 400 行
4. 审查判 PASS（含北极星相关性）
5. **合并后自检**：merge 到 main 后再跑一次全量，挂了 → **自动 `git revert` 该 merge**
6. **Kill 开关**：仓库根存在 `STOP_LOOP` 文件 → 本轮结束后停（用户随时可喊停）

## 机制（方案 A：主循环编排）
- Opus 主循环逐轮发起：策划/推进/审查为独立 subagent（按难易选模型：策划/审查用 opus，
  机械 build 可降 sonnet），主循环执行**闸门 + 合并**——始终在环里当最后把关人。
- 合并即更新本地 main 检出（`git -C <main> merge --ff-only`），让 launchd 定时报告用上新代码。

## 节奏 & 预算
- **连续模式**（现在起，2026-06-25 周四中午）：逐轮跑到周额度烧完或 2pm 重置；某轮跨 2pm 先收尾该轮。
- **定时模式**（2pm 额度重置后）：落地 launchd 每晚非交易时段一轮。
- 每轮预算上限防单轮失控；STOP_LOOP 或无题可做即停。

## 留痕
每轮在 `进展.md` 现在段记一行「本轮选题 + 预期指标 + 实际结果」，决策史按需补。
