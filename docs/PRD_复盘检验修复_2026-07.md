# PRD：复盘检验问题修复（一致性校验 · 去保守化 · 周期性复盘）

> 依据：2026-07-21/23 ultracode 多代理审查（对抗验证过）+ agent.db 真实数据复盘。
> 北极星对齐：三项全部服务于「证明建议价值 + 让用户敢照着做」。
> 范围外：飞书卡 v2.0 字号迁移（需实机验证，另立一轮）；本 PRD 不改任何选股/打分数值口径。

## 背景（问题实锤）

1. **跨报告矛盾**：`weekly/drift.py` 的 `derive_guidance()` 单票超 15% 直接生成"减仓"，纯看市值占比，完全不读日报 recommendations 表。极端场景：日报刚说"加仓"、同周周报说"减仓"，系统毫不知情。目前**全项目无任何跨报告一致性校验**。
2. **措辞过度保守**（用户体感属实，逐条验证）：
   - `weekly/allocation_advisor.py:82` entry_hint 明令"不要预测具体价格"，可执行性被阉割；
   - 全项目约 12 处重复"仅供参考/不构成投资建议"（workflow.py:551/597、weekly/report_card.py:217、monthly/review.py:322、morning/note.py、value/report.py、alerts/news_monitor.py、monthly/scorecard.py、monthly/playbook.py、weekly/daily_followup.py 等），"仅供参考"暗示建议不可信；
   - `agents/portfolio_manager.py:238` 数据异常兜底也返回"观望"，污染真实观望信号和胜率统计。
3. **行为闭环断档**：user_actions 最后记录 2026-06-30，近 3 周无法复盘用户行为；且"持仓分层操作建议"（不动/分批抄底/该减照减）目前只存在于一次性人工分析，无周期性机制。

## P1 跨报告一致性校验

**改动**：在 `weekly/allocation_advisor.py` 调用 `derive_guidance()` 之后（不在 drift.py 内部——保持其纯函数、无 DB 依赖），对每条 减仓/建仓 guidance 调用 `db/tracker.py: get_latest_recommendation(ticker)`：
- 方向冲突（日报最近裁决为 加仓/买入 而周报要 减仓，或反向）→ **不隐藏、不删除**，在该条 guidance 的 rationale 追加："⚠️ 与近日日报方向不同：本条因持仓集中度红线触发，非基本面转空"。
- 参照范式：`alerts/news_monitor.py: _validate_dip_plan()` 自洽性闸门。

**验收**：单测覆盖 ①冲突场景追加标注 ②无冲突不追加 ③查无日报记录时静默跳过。不改 target_pct/action 计算口径。

## P2 去保守化（三子项）

**P2a 免责声明统一**：全项目"仅供参考/不构成投资建议"句式（约 12 处）替换为中性单句："以上为系统依据当前数据给出的明确建议，仓位调整请结合自身风险承受能力执行"，且**每份报告只在结尾出现一次**（同一卡片内多处的删到只剩一处）。
- 例外不动（4 处，均为"信号/数据可靠性提示"而非免责声明，opus 审查确认）：
  - `agents/portfolio_manager.py:156` 技术信号失效提示；
  - `alerts/news_monitor.py:941` 高波动品种价格锚提示；
  - `monthly/scorecard.py:120` 数据不足评分提示；
  - `alerts/news_monitor.py` 中与上述同性质的信号失效句式。

**P2b entry_hint 允许规则触发条件**：`weekly/allocation_advisor.py` prompt 改为：给出可验证的量化触发条件（如"回落到 250 日均线附近 / PE 低于 X 倍 / 较 52 周高点回撤 Y% 时分批介入"），仍禁止"预测式喊价"（不许说"我预测会跌到多少"）。

**P2c 观望兜底打标**：`agents/portfolio_manager.py` 异常兜底返回 dict 增加 `is_fallback: True`（recommendation 仍为"观望"，**不新增枚举值**——避免打穿 main.py `_WATCH_ALLOWED`、workflow.py EMOJI/TEMPLATE、value/metrics.py 与 db/tracker.py `_PASSIVE_RECS` 等至少 6 处硬编码映射）：
- 卡片渲染命中标记 → 文案追加"⚠️ 数据异常兜底"；
- `value/metrics.py` 胜率统计将 is_fallback 样本排除出"真实观望"。

**验收**：P2a 后 grep 全项目"仅供参考"只剩两处例外；P2b 只改 prompt 字符串不动 JSON schema；P2c 有单测覆盖 fallback 标记透传与统计排除。

## P3 周期性复盘 + 分层操作建议

**P3a 记账断档提醒**：周报生成时查 `user_actions` 最新记录日期，距今 >7 天 → 周报卡追加一条："📒 已 N 天未记录操作，行为复盘停摆中——有买卖请 `log-action` 补记"。（查询只读，失败静默跳过不影响周报主体。）

**P3b 周报分层操作段**：周报新增"持仓分层"小节，按 recommendations 表每票最近一次裁决聚合为三层：**拿住不动 / 回调分批可加 / 该减照减**，每层列 ticker（复用现有五档裁决，不新增判断逻辑、不调 LLM）。让"抄底还是放着"这个问题每周自动有答案，而非靠人工跑一次。

**验收**：单测 ①断档 N 天计算与文案 ②分层聚合正确（含空层不渲染）③user_actions 为空时提醒仍能出。

- 所有文案改动数字信息零折损；新文案遵守白话+黑话注释规范。
- 全量 `uv run pytest tests/ -q` 通过（已知豁免：test_guards.py 的 portfolio.yaml worktree 缺失项）。
